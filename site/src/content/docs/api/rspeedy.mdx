# Rspeedy

Compile styles in Lynx applications built with Rspeedy.

The `zyzz` function from `zyzz/rspeedy` returns an Rsbuild plugin for the Rspeedy `plugins` list. It compiles the project, rewrites authoring calls, and serves the combined stylesheet as the `zyzz.css` module. Importing that module from the entry adds the styles to the Lynx bundle.

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { pluginReactLynx } from '@lynx-js/react-rsbuild-plugin'
import { zyzz } from 'zyzz/rspeedy'

export default defineConfig({
  // [!code hl:2]
  // Compiles before the ReactLynx transforms run
  plugins: [pluginReactLynx(), zyzz({ root: 'src' })],
})
```

## Installation

The package is published as `zyzz-lynx`. Install it under the `zyzz` alias, since the compiler recognizes authoring imports from `zyzz`.

```sh
# Keeps `import { style } from 'zyzz'` in application code
pnpm add zyzz@npm:zyzz-lynx
```

## Stylesheet

Import `zyzz.css` once from the application entry. The module contains shared contributions, then module styles with dependencies first, and Rspeedy compiles it with the rest of the entry's CSS.

```tsx title="src/index.tsx"
// [!code hl:2]
// Adds the compiled styles to the Lynx bundle
import 'zyzz.css'
import { root } from '@lynx-js/react'
import { App } from './App'

root.render(<App />)
```

Each environment compiles separately, so `lynx` and `web` environments receive their own stylesheet. Watch rebuilds recompile the stylesheet after any source edit.

With [`options.inject`](#optionsinject), the plugin imports `zyzz.css` ahead of every entry's own modules instead. A manual import then resolves to the same module, which stays in its injected position.

## Variants

The Lynx template encoder drops nested rules, `:where()`, and attribute selectors, so the plugin compiles every environment for the `lynx` target. Recipes select with classes by default, and each choice and compound becomes one rule under its own class, which the application adds. `selection: 'className'` returns that class list for a `className` prop.

```tsx title="src/Badge.tsx"
import { variants } from 'zyzz'

export function Badge(props: { tone: 'neutral' | 'success' }) {
  // [!code hl:2]
  // Renders "z_… zv…1" and the compound class when both choices match
  return (
    <text className={styles.badge({ size: 'large', tone: props.tone })}>
      Paid
    </text>
  )
}

namespace styles {
  export const badge = variants({
    base: { padding: '2px' },
    // Emits .zv…4 { opacity: 0.5 }, selected by the application, not .zv…0.zv…3
    compoundVariants: [
      { style: { opacity: 0.5 }, when: { size: 'large', tone: 'success' } },
    ],
    selection: 'className',
    variants: {
      size: { large: { height: '40px' }, small: { height: '20px' } },
      tone: { neutral: { color: '#000' }, success: { color: '#0a0' } },
    },
  })
}
```

Every emitted rule selects one class, so a compound keeps the specificity of a choice, and a later definition or `cx` argument still overrides it by order. A `cx` composition copies the recipe rules under its own prefix and renames the choice classes, so argument order holds as on the web. An at-rule inside a choice wraps the class rule instead of nesting in it.

- **`selection: 'attribute'`:** A compile error, since Lynx matches no attribute selector. Spreads of the default class selection return `className` and `style` props.
- **`conditions`:** A compile error. Nest `@media` queries inside the choice styles instead.
- **Dynamic choices:** Supported with spreads, which carry the bound variables in `style`, and rejected by `selection: 'className'`.

## Loader Order

The plugin rewrites each module before any other loader, including `enforce: 'pre'` loaders from other plugins or `tools.rspack`. Those loaders receive the compiled module.

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { zyzz } from 'zyzz/rspeedy'

export default defineConfig({
  plugins: [zyzz()],
  tools: {
    rspack: {
      module: {
        rules: [
          // [!code hl:2]
          // Runs after Zyzz despite the pre stage
          { enforce: 'pre', test: /\.tsx?$/, use: ['./scripts/loader.ts'] },
        ],
      },
    },
  },
})
```

## Signature

```ts
// Returns an Rsbuild plugin
zyzz(options?)
```

## Parameters

### options.compiler

- **Type:** `boolean{:ts}`
- **Default:** `true{:ts}`

Rewrites authoring calls into compiled props. With `false`, the stylesheet is still produced but the authored calls stay, so identity-bearing declarations need explicit identities.

```ts title="lynx.config.ts"
import { zyzz } from 'zyzz/rspeedy'

// [!code hl:2]
// Keeps authored calls in the bundle
const plugin = zyzz({ compiler: false })
```

### options.inject

- **Type:** `boolean{:ts}`
- **Default:** `false{:ts}`

Imports `zyzz.css` before the modules of every entry in every environment, so entries need no import of their own. A manual import of `zyzz.css` stays safe and adds no second copy of the rules.

```ts title="lynx.config.ts"
import { zyzz } from 'zyzz/rspeedy'

// [!code hl:2]
// Adds zyzz.css to the start of every entry
const plugin = zyzz({ inject: true })
```

The injected stylesheet precedes every stylesheet an entry imports, even one imported before a manual `import 'zyzz.css'`. Those later rules win ties in specificity. Keep the option off to control the order from the entry, or use cascade layers on Lynx versions that support them, from 4.2.

```css title="src/app.css"
/* Overrides a zyzz.css rule of equal specificity, since it comes later */
.title {
  color: red;
}
```

### options.reset

- **Type:** `boolean{:ts}`
- **Default:** `false{:ts}`

Adds the packaged [reset](/docs/guides/reset) to `zyzz.css`, in a `reset` layer ordered before authored layers. The reset selects HTML elements, which Lynx pages do not render.

```ts title="lynx.config.ts"
import { zyzz } from 'zyzz/rspeedy'

// [!code hl:2]
// Prepends the reset layer to zyzz.css
const plugin = zyzz({ reset: true })
```

### options.root

- **Type:** `string{:ts}`
- **Default:** the Rspeedy project root

The source directory to compile. Every module under it contributes CSS, including unimported global styles. Hidden directories, `node_modules`, `dist`, `build`, `coverage`, tests, fixtures, and declaration, test, and benchmark modules are skipped.

```ts title="lynx.config.ts"
import { zyzz } from 'zyzz/rspeedy'

// [!code hl:2]
// Leaves lynx.config.ts and other project files uncompiled
const plugin = zyzz({ root: 'src' })
```

## Returns

### plugin

- **Type:** `RsbuildPlugin{:ts}`

A plugin that registers the Zyzz Rspack plugin in each environment and resolves `zyzz.css`.

```ts title="lynx.config.ts"
import { defineConfig } from '@lynx-js/rspeedy'
import { zyzz } from 'zyzz/rspeedy'

export default defineConfig({
  // [!code hl:2]
  // Accepted wherever Rspeedy takes Rsbuild plugins
  plugins: [zyzz()],
})
```

## Errors

Builds fail on unsupported authoring, unresolved dependencies, and source changed by a transform that ran first. Rspeedy resolves imports with its own extensions, so an import such as `./App.js` must name a file that exists.

```tsx title="src/index.tsx"
// [!code hl:2]
// Resolves App.tsx through Rspeedy's extension list
import { App } from './App'
```
