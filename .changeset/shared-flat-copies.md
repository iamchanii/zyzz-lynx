'zyzz-lynx': patch
---

Flat Lynx compositions, which production builds composing independently concatenate argument by argument, kept the override copies of each `cx` call under a class prefix of its own and shared a copy only within one argument, so three sibling `cx(base, solid && styles.x())` calls printed the same `background-color` copy three times. The copies of every flat composition in a module now share one style and one prefix, and a later argument reuses an existing copy with the same conditions and declaration whenever stylesheet order still lets it win: the copy's rule index exceeds that of every copy the call referenced before it whose declaration conflicts with the item. In `cx(a(blue), b(red), c(green), d(red))`, `d` still gets a copy of its own after `c`'s, while `cx(a(blue), b(red), c(red))` and a sibling `cx(a(blue), e(red))` print one red copy. A recipe argument applied with literal choices, such as `styles.badge({ tone: 'loud' })`, `{ tone: null }`, or an omitted axis taking its default, copies only the choices the application can select and counts only those choices as earlier declarations for later arguments, while a runtime choice keeps every choice's copies.
