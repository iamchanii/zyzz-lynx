'zyzz-lynx': minor

Lynx production builds composing independently, the `zyzz/rspeedy` default, compiled a `cx` call of local styles and class-selection recipe applications with conditional arguments to one class list per presence alternative and recipe choice, so a calendar cell with four conditions held tables of 140 entries in both thread chunks, and the stylesheet repeated every declaration of the composed styles once per alternative. Such a call now concatenates its arguments' own class lists, each conditional argument behind its condition and each recipe argument through a selector over its own choices, as `"z3 z4"+((today)?" z5":"")`. Every argument keeps the rules it emits alone, and a declaration that conflicts with an earlier argument's under the same condition gets one copy under a class of the call, printed after every shared rule in argument order, so later arguments win by stylesheet order whichever arguments are present. Compositions with imported styles, aliased arguments, repeated recipes, compounds, recipe conditions or payloads, nested compositions, or HTML output keep the runtime helper or the class tables, as do development builds, ordered composition, and the web target.
